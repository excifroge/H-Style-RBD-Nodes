# H-Style RBD Nodes: Handoff Notes for AI Assistants

This file is written for an AI coding assistant that has been asked to explain, change or extend this
Blender extension. It gives the technical background that is not obvious from reading one file at a time:
how the parts fit together, which names are contracts, what Blender does that will surprise you, and how to
check your work. The user manual is the README ([English](README.md), [Japanese](README_JA.md),
[Chinese](README_ZH.md)); it says what every input does from the user's side and is not repeated here.

## 1. What this project is

A Blender extension (Blender 5.2 LTS or newer, Python only, no binaries, Blender itself is not modified)
that provides rigid body destruction for game VFX as a family of Geometry Nodes node groups:

    model -> RBD Material Fracture -> (RBD Configure, RBD Cluster, ...) -> RBD Bullet Solver -> baked motion
          -> export: bone FBX / rigid-body VAT (textures + Unity shader and player) / Alembic

"H-Style" is this project's name for the conventions the node family follows:

- one node per task, with the node names listed in section 4;
- three geometry streams passed from node to node: `Geometry`, `Constraint Geometry`, `Proxy Geometry`
  (two nodes are not on the streams: `RBD Select` outputs a boolean field and takes no geometry,
  `RBD Exploded View` takes and returns `Geometry` only);
- data travels as named attributes on those geometries (`piece_id`, `active`, `v`, `strength` ...);
- a constraint is an edge between the centres of two pieces, with a `strength`;
- the solver reads what arrives at its inputs, not a settings panel somewhere else.

The one thing that cannot follow the convention: Bullet cannot run while a node tree is evaluated. The
`RBD Bullet Solver` node therefore does not simulate. A Bake operator runs the simulation from Python and
writes the result back into the node, which then plays it.

## 3. Architecture in one page

```
            Geometry Nodes evaluation (Blender)                    Python (this add-on)
  +--------------------------------------------------+   +-----------------------------------------+
  | object's modifier tree:                          |   |  ui.py      operators, panels, menu     |
  |   Group Input -> RBD nodes ... -> RBD Bullet     |   |  graph.py   read what flows into a node |
  |   Solver -> Group Output                         |<->|  sim.py     Bullet bake, cache, events  |
  |                                                  |   |  export.py  FBX, VAT, Alembic           |
  | each RBD node = a node group built by            |   |  nodes_*.py build the node groups       |
  | nodes_rbd.py with nodekit.Builder                |   |  nodekit.py the builder                 |
  +--------------------------------------------------+   +-----------------------------------------+
```

A bake, step by step (`sim.bake_many`):

1. `nodes_rbd.refresh()` brings node groups from older versions of the add-on up to date.
2. The settings are read from the inputs of the solver node of the first object (`sim.settings_from_node`).
3. For every object, `graph.pieces`, `graph.constraints` and `graph.proxy` read the three streams that arrive
   at the solver node. They do it by rewiring the tree's Group Output to the source of that input for a
   moment (`graph.shown`), evaluating the object, and putting the wiring back.
4. A temporary scene with a rigid body world is created. Every piece becomes a temporary object with a
   convex hull shape (from the proxy points of the piece), every constraint a breakable FIXED rigid body
   constraint, the ground a large box, every collision object a passive animated copy. Force field objects
   of the user's scene are linked in as they are.
5. Frames are stepped one at a time. Before each frame, pieces whose release frame has come are handed to
   the solver (see "hand-over" in section 7).
6. Positions and rotations of all pieces on all frames are recorded, cleaned up (`settle`), and crack events
   are derived (`crack_events`).
7. Results are written for all objects or for none (`write_cache(defer=True)` returns `(undo, finish)`).
   The temporary scene and everything in it is removed.

After a bake the solver node's `Baked` input is on and its output is the playback group (`nodes_playback`)
applied to the pieces as they were at bake time ("frozen pieces"). Upstream edits no longer change the
picture until the user bakes again or frees the bake. The cache and the frozen pieces are ordinary objects
stored in the `.blend`, so a baked file plays on a machine that does not have the add-on installed.

## 4. The nodes

All are built in `Extension/nodes_rbd.py` and listed in `nodes_rbd.NODES = {kind: (name, ensure_function)}`.

| Node (group name) | kind | What it does |
|---|---|---|
| `RBD Material Fracture` | `material_fracture` | Cuts a closed mesh into pieces (Concrete / Glass / Wood), makes constraints from shared cut faces, makes the proxy |
| `RBD Assemble` | `assemble` | No cutting: every loose part of the mesh is a piece |
| `RBD Constraints From Rules` | `constraints_from_rules` | Constraints between pieces whose surfaces are closer than a search radius |
| `RBD Configure` | `configure` | Writes `active`, `v`, `w`, `activate_time`, `density`, `friction`, `bounce` on selected pieces |
| `RBD Constraint Properties` | `constraint_properties` | Sets or multiplies `strength` on selected constraints |
| `RBD Cluster` | `cluster` | Groups pieces into clusters, scales the strength of constraints inside a cluster |
| `RBD Select` | `select` | Outputs a boolean field: below a height, in a box, in a sphere, by attribute |
| `RBD Exploded View` | `exploded_view` | Pushes pieces apart for inspection |
| `RBD Bullet Solver` | `bullet_solver` | Holds the solver settings and, after a bake, plays the result |

`RBD Material Fracture` wraps one inner node, the kernel group `RBD Fracture` (`nodes_fracture.py`, kind
`fracture`), which does the actual cutting. A Voronoi cell is built as the dual of a convex hull and
intersected with the model by Mesh Boolean.

A node group is recognised by the custom property `hrbd_kind` on its node tree (the kind above), never by
its name. A second property, `hrbd_version`, is not part of the recognition: it only decides whether the
group has to be rebuilt.

## 5. Contracts: names that other code or saved files depend on

Changing any of these breaks files that users have saved, or the link between nodes and Python.

**Attributes on `Geometry`** (point domain unless noted; the solver takes the average over each piece)

| Name | Type | Written by | Meaning |
|---|---|---|---|
| `piece_id` | int | Fracture, Assemble | Which piece a vertex belongs to, 0..N-1 |
| `inside` | bool, face | Fracture, Assemble | The face was made by a cut |
| `rbd_pivot` | vector | Fracture, Assemble | Centre of the piece as the **average of its vertices**. The nodes use it (Select, Cluster, Exploded View). The simulator does not: it computes the centre of mass from the volume (`EvalMesh.piece_centroids`), and that is the pivot stored in the cache |
| `rbd_rest` | vector | Fracture, Assemble | Position before interior detail was added |
| `active` | bool | Configure | False: never moves, still collides (becomes a PASSIVE body) |
| `v`, `w` | vector | Configure | Velocity (metres per second) and angular velocity (radians per second) at hand-over. Directions in object space, sizes in world units. Either one alone is enough; a piece with neither starts at rest |
| `activate_time` | float | Configure | Seconds after the start frame at which the piece is handed to the solver |
| `density`, `friction`, `bounce` | float | Configure | Negative means "not set": the solver node's value is used |
| `cluster` | int | Cluster | Cluster number |

`core.PIECE_ATTRIBUTES` lists the ones Python reads; `core.EvalMesh.per_piece(name)` averages them.

**Attributes on `Constraint Geometry`**: `piece_id` (int, point: the piece that end of the edge holds),
`strength` (float, edge), `area` (float, edge), `anchor` (vector, edge: where the two pieces touch).
`strength` is not a force. The constraint breaks when the impulse on it exceeds
`strength x mass of the lighter of the two pieces` (`breaking_threshold` in `bake_many`), so the same
strength holds small and large pieces about equally well. Constraints only join pieces of the same object.

**Solver node inputs** are used by name. There are four kinds, and they behave differently:

| Kind | Inputs | Who uses them, and when |
|---|---|---|
| Streams | `Geometry`, `Constraint Geometry`, `Proxy Geometry` | Wired. Read at bake time by `graph.pieces`, `graph.constraints`, `graph.proxy` |
| Bake settings | `Start Frame`, `End Frame`, `Bullet Substeps`, `Constraint Iterations`, `Glue Iterations`, `Density`, `Bounce`, `Friction`, `Collision Padding`, `Linear Damping`, `Angular Damping`, `Start Asleep`, `Collision Objects`, `Ground Plane`, `Ground Height`, `Gravity`, `Force Fields`, `Field Weight`, `Limit To` | Read once, at bake time, by `sim.settings_from_node` through `graph.value`, which raises an error if the input is wired. They must hold plain values. Changing one after a bake changes nothing until the next bake |
| Playback | `Time Scale`, `Frame Offset` | Used inside the node tree, live. They change the picture of an existing bake at once and may be wired or animated. Python does not read them |
| Cache | `Baked`, `Cache`, `Frozen Pieces`, `Piece Count`, `Frame Count`, `Cache Start Frame` (`sim.SITE_INPUTS`) | Written by the bake and cleared by Free Bake. Not meant to be edited by hand; the panel is closed by default |

**The cache** is an object named `RBD Cache.<object>` whose mesh has `frames x pieces` points
(index = `frame * pieces + piece`): position = centre of mass of the piece on that frame, attribute `rot`
(quaternion, wxyz), attribute `pivot` (centre of mass at rest). Custom properties on the object: `rbd_pieces`,
`rbd_frames`, `rbd_frame_start`, `rbd_fps`, `rbd_impact`, `rbd_events` (6 numbers per crack event: frame
index, x, y, z, size, speed), `rbd_contacts` (6 numbers per contact: piece a, piece b, x, y, z, area).
`sim.read_cache(ob)` returns `(pos[F,N,3], quat[F,N,4], pivots[N,3], frame_start)`.
All of these positions are in **world space as it was at bake time**, not in the object's space. The cache
object's world matrix is a copy of the baked object's world matrix at that moment; playback uses it to go
from the frozen pieces to that world frame and back, so a baked object can be moved, rotated or parented
afterwards and the destruction follows it. The frozen pieces are an object `RBD Rest.<object>`.
Helper objects carry the custom property `hrbd_helper`.

Reading the cache from a script (run inside Blender with the add-on enabled; checked against what the
viewport shows after the object was moved and rotated: the same within 0.001 mm):

```python
import bpy, importlib
from mathutils import Quaternion, Vector
package = next(a.module for a in bpy.context.preferences.addons if a.module.endswith("h_style_rbd_nodes"))
sim = importlib.import_module(package + ".sim")       # the package is bl_ext.<repository>.h_style_rbd_nodes

ob = bpy.data.objects["Wall"]
pos, quat, pivots, start = sim.read_cache(ob)          # read_cache returns None if there is no complete bake
cache = sim.cache_info(ob)[0]                          # the cache object; do not look it up by its name
i, frame = 7, 20                                       # piece_id, scene frame
p = Vector(pos[frame - start, i].tolist())             # centre of mass, world space at bake time
q = Quaternion(quat[frame - start, i].tolist())        # turn from the rest pose about that centre, same axes
to_now = ob.matrix_world @ cache.matrix_world.inverted()
p_now = to_now @ p                                     # where that centre is in the world now
# a vertex of the piece, v_rest being its position in the mesh of the frozen pieces object:
# v_now = to_now @ (p + q @ (cache.matrix_world @ v_rest - Vector(pivots[i].tolist())))
```

`frame - start` indexes the bake as it was recorded. What the viewport shows is the cache at
`(scene frame - Cache Start Frame) x Time Scale + Frame Offset`, clamped to the baked range and
interpolated between two cache frames (`nodes_playback`).

**The VAT export** writes schema `hrbd_vat_1` (`export.VAT_SCHEMA`); the layout is described in the README
and in the header of `Extension/HStyleRbdVAT.hlsl`. The Unity files check the schema string.

**Operators**: `hrbd.setup`, `hrbd.add_node`, `hrbd.check_mesh`, `hrbd.cursor_to_input`, `hrbd.bake`,
`hrbd.free_bake`, `hrbd.export_fbx`, `hrbd.export_vat`, `hrbd.export_alembic`.

## 6. Module guide

**`nodekit.py`**: `Builder` writes a node group. `b.input(name, kind, default, ...)` adds an interface
input and returns its socket (`kind` is one of `geo float int bool vec mat obj col img str rot`);
`b.panel(name, closed=...)` starts a panel; `b.input(..., toggle=True)` as the first input of a panel makes
it the panel's checkbox; `b.menu(name, items, default)` adds a drop-down and returns
`pick(data_type, {item: value})`; `b.node(idname, {input: value}, **props)`, `b.group(tree, {...})`,
`b.switch`, `b.math`, `b.vmath`, `b.cmp`, `b.bmath`, `b.named`, `b.store`, `b.capture`, `b.set_pos` are
shorthands; `b.output(...)`; `b.finish()` lays the nodes out and stamps the version.
`ensure_group(kind, version, build)` returns the existing group or (re)builds it. A rebuild happens in
place, so users of the group keep pointing at it; the values and wires of every modifier and node that uses
the group are saved before and restored after, **by socket name**.

**`nodes_fracture.py`**: the cutting kernel. Also still usable directly as a modifier (the legacy path,
see section 10).

**`nodes_rbd.py`**: the nodes of section 4. `constraint_network` finds neighbours of fractured pieces by
"twin faces" (two neighbours have the same polygon on the cutting plane, facing opposite ways);
`proximity_network` finds neighbours of any pieces by scattering points on the surfaces and asking which
surface is nearest half a search radius ahead; `_bonds` turns either into one edge per pair, and drops a
pair whose contact area is less than a fraction of the median contact area of the object. That fraction is a
fixed number in each caller: 0.001 for twin faces, 0.05 for the proximity search. It is a ratio, not an area.
`refresh()` brings the groups of the file up to date, one group per kind: `nodekit.find_group(kind)` returns
the **first local** group that carries that kind. What follows from it: a group linked from another file is
never touched; if the user duplicated a group (a second group with the same `hrbd_kind`), only the first
one found is upgraded, and nodes pointing at the copy keep the old interface.

**`nodes_playback.py`**: reads the cache and moves the pieces. Pure lookup and interpolation.

**`graph.py`**: finds RBD nodes in an object's modifiers (`sites`, `solver_site`) and reads what flows
into a node's input (`shown`, `pieces`, `constraints`, `proxy`, `open_edges`). The search is shallow: only
group nodes placed **directly** in the node tree of a Geometry Nodes modifier are found, in modifier order
and then in the order the nodes were made. A solver node inside a user's own nested group is not seen, and
if an object has several solver nodes the first one is the one that is baked.

**`core.py`**: `EvalMesh` (the evaluated mesh as numpy arrays, with per-piece helpers: `n_pieces`,
`per_piece`, `piece_volumes`, `piece_centroids`, `vertex_means`, `open_edges`), and helpers to get and set
modifier inputs by name (`get_input`, `set_input`).

**`sim.py`**: the bake (`bake_many`), settings (`SimSettings`, `settings_from_node`), cache
(`write_cache`, `read_cache`, `free_cache`, `cache_info`, `rest_pieces`), post-processing (`settle`,
`crack_events`, `unbroken_groups`), and the reference neighbour search in Python (`adjacency`) that the
tests compare the node version against. `settle` freezes a piece in its final pose from the frame after
which it never again leaves that pose by more than 0.5 mm or 0.1 degrees (solver jitter is removed, real
motion is kept). `crack_events` follows each contact point with both of its pieces; the last frame on which
the two copies part for good is when that crack opened.

**`export.py`**: `export_fbx` (one bone per piece), `export_vat`, `export_alembic`; `piece_shader_data`
makes the per-piece vertex colours. `Merged` merges pieces that never separate: pieces whose recorded contact
points stay together for the whole bake form a group, one piece's motion stands for the group, every piece is
then checked against the tolerance and leaves the group if it would deviate more, and a cut face whose
corners are all shared with another piece of the same group is dropped as hidden.

**`ui.py`**: operators, the `Add > RBD` menu, and two panels that draw the inputs of the RBD nodes of the
active object with `layout.template_node_inputs(node)`. `TEMPLATES` are the networks the set-up operator
builds. `PANEL_TEXT` lists text drawn by hand, for the translation check. A `load_post` handler calls
`nodes_rbd.refresh()`.

**`translations.py`**: Simplified Chinese interface text (`ZH`). Node names are never translated.

## 7. Blender behaviour that will surprise you

Each of these was measured in Blender 5.2 and cost time. Read before changing the related code.

Node groups

- A **menu socket** takes its items from the one Menu Switch node it is wired to. Wire it to several and it
  becomes undefined. `Builder.menu` therefore makes a single Menu Switch and drives ordinary Switch nodes
  from its "this item is chosen" outputs.
- A **panel toggle** socket is addressed on the node by the **panel's name**, not by its own name:
  `node.inputs["Constraints"]`, not `node.inputs["Create Constraints"]`.
- Blender **hides or greys out inputs that cannot affect the outputs**. Use it: route everything of a panel
  through the material `pick` and the panel disappears for materials that do not use it. Work around it:
  the solver node's settings affect nothing inside the tree, so they are summed into a Switch that never
  switches (the `read` list in `build_bullet_solver`). A new solver input must be added to that list or it
  will be hidden.
- **Changing a group's interface** from Python removes and recreates sockets, with new identifiers. Every
  node using the group would lose its values and wires; `nodekit` restores them by name. Consequences:
  bump the group's version whenever its build function changes, and treat a renamed input as a removed one.
  **Keyframes and drivers are not restored**: Blender deletes them together with the old sockets (measured:
  a keyframed `Time Scale` is a constant after the rebuild). Nothing in the add-on brings them back yet.
- A Switch is lazy, but if the same geometry also feeds a **nested group node**, it is evaluated every time.
  That is why playback reads the frozen pieces object instead of the node's own input.
- In about one freshly built group in four, a Switch branch that is not selected is **evaluated anyway**
  inside a For Each zone. Make an extra evaluation harmless instead of relying on laziness.
- **Mesh Boolean** carries face attributes, UVs, materials and colours to the result, but not vertex groups
  (hence `Keep Vertex Group`, which samples the nearest surface of the source). The Manifold solver returns
  nothing for non-manifold input; the kernel then falls back to the Exact solver per piece.
- Modifier inputs are read and written through `core.get_input` / `core.set_input`. Do not write
  `modifier["Socket_x"]`.
- Removing a modifier does not lower the user count of objects its inputs pointed at. `sim._in_use` scans
  the real references before a helper object is deleted.

Rigid bodies

- A body gets the velocity of an animated move only if the move does not happen on the first simulated
  step. The simulation therefore starts `PRE_ROLL` (1) frame early.
- **Hand-over**: a piece that must wait (lead-in frame, `activate_time`, or one frame of animated motion that
  gives it `v`) is held as "Animated" *and* not "Dynamic" (`rigid_body.kinematic = True`,
  `rigid_body.enabled = False`). The loop that steps the frames flips both when the release frame comes.
  Two reasons, both measured: keyframes on these properties are not ordered against the simulation step
  (the release came one frame late in about four bakes out of ten), and force fields act on animated
  bodies, piling up force until release, unless the body is not Dynamic.
- During the one animated frame that gives a piece its `v`, nothing collides. The move is clamped at the
  ground; pieces can pass through each other a little.
- **Force fields**: a field of strength S pushes each body with S / frame-rate newtons, whatever the
  substeps. `effector_weights.all` also multiplies gravity, so the Field Weight is written to each field
  type's own weight (`sim.FIELD_WEIGHTS`), never to `all`.
- A Box collision shape is centred on the object's origin; the ground mesh is built around its origin.
- FIXED constraints are rubbery with the default iterations. Each one gets its own solver iterations
  (`Glue Iterations`).
- A collider whose shape changes over time updates once per frame and hits too hard. An object that was
  itself baked by this add-on is not a reliable collider; simulate the objects together instead.

Other

- Blender's own dictionary wins for interface words it already translates, and node group sockets have no
  translation context. Pick input names that Blender does not mistranslate.
- A `.blend` saved on any machine stores the start folder of the Shading workspace's file browser, which is
  the user's Documents folder. `Examples/make_examples.py` overwrites that buffer before saving;
  `Tools/blend_strings.py` checks a file (a `.blend` is Zstandard compressed, a plain search finds nothing).
- `blender --command extension build` and `validate` need `--factory-startup` when run in the background.
- A zip stores the clock time of every file without a time zone, so an ordinary build tells where and when it
  was made. `Tools/build.sh` copies the files to a staging folder and gives them one fixed date; the same
  source then also gives the same zip byte for byte.
- Tools that need a window register a quit timer as their first action, so a script error cannot leave a
  window open.

## 8. Tests

Requirements: Blender 5.2+ and bash. Point `BLENDER` at the executable if it is not on the PATH.

```bash
BLENDER=/path/to/blender bash Tests/run_all.sh              # six suites, headless
BLENDER=/path/to/blender bash Tests/run_all.sh --installed  # also: validate, build the zip, install it into
                                                            # a throw-away config (Tools/UserResources) and
                                                            # run the add-on suite against the installed copy
blender --background --factory-startup --python-exit-code 1 --python Tests/test_nodes.py -- Tests/Out forces
```

Every check has a threshold and a name; a suite exits non-zero if one fails. Results go to `Tests/Out/*.json`.
A single case can be named after the output folder, as in the last line above.

| Suite | Covers |
|---|---|
| `test_fracture.py` | The cutting kernel: volumes, closed pieces, attributes, UVs, normals, the three patterns |
| `test_nodes.py` | The RBD nodes end to end. Cases: `material_fracture` (constraint network against the Python reference), `solver`, `pieces` (Assemble, rules, proxy), `forces` (hand-over timing, initial velocity and spin, force fields), `upgrade` (old groups keep values and wires) |
| `test_bake.py` | The solver through the legacy path: glue, clusters, anchors, activation, events, cache, undo on failure |
| `test_export.py` | FBX, VAT, Alembic read back and compared with the bake; merging |
| `test_stress.py` | Awkward models through the node workflow: open, non-manifold, scaled, parented, tiny, huge, far from the origin |
| `test_addon.py` | The operators in the order a user presses them, save and reload |

The number of checks changes with every feature, so it is not written here: each suite prints
`passed/total` as its last line and the same numbers are in its `.json`.

`Tests/common.py` has the mesh builders and the `Report` / `check` helpers. If a check fails once and passes
on a rerun, find out why; two long-standing "flaky" checks turned out to be the hand-over problem above.

Unity side (optional, needs Unity 6000.0 with URP): `Tests/unity_export.py` writes an export,
`Tests/Unity/Fresh/run_fresh.sh` drops it into an empty project in batch mode and checks that the scripts
compile, the set-up menu works and the player emits particles at the cracks in Play mode.

## 10. Legacy parts

The project started with a side panel and a kernel modifier placed directly on the object. That path still
exists. Three suites (`test_fracture`, `test_bake`, `test_export`) use it through `Tests/common.add_fracture`,
and so do `Tests/unity_export.py` (the export the Unity check reads) and `Tests/bench_heavy.py`:

- the kernel group used as a modifier (`core.find_modifier(ob, core.KIND_FRACTURE)`) plus a separate
  `RBD Playback` modifier;
- `SimSettings` fields that the node workflow does not use: `use_glue`, `glue_strength`, `glue_variation`,
  `cluster_pieces`, `anchor_bottom`, `anchor_height`, `activation*`, `burst_*`; `glue_plan`, `clusters`,
  and the glue preview functions.

Nothing in the interface reaches it. It is safe to remove once those five files are ported to the node
workflow; until then, a change in `sim.py` has to keep both paths working (`job.site is None` marks the
legacy path).

## 11. How to make common changes

**Add an input to an existing node**
1. Add `b.input(...)` in its build function and use the socket. If nothing in the tree uses it (solver
   settings), add it to the `read` list.
2. Bump the group's version (both in `Builder(...)` and in its `ensure` function; the solver uses
   `SOLVER_VERSION`, the fracture node `VERSION`).
3. If Python reads it: add the field to `SimSettings`, read it in `sim.settings_from_node`, and **use it in
   `bake_many`**. An input that shows up and is read but changes nothing is the easy mistake here. Look at
   the branches around the place where you apply it (`Start Asleep`, the hand-over) for cases they decide.
4. Add the Chinese text to `translations.ZH`, run `Tools/ui_strings.py`.
5. Add a check to `Tests/test_nodes.py`; run the `upgrade` case to see that old files keep their values.
6. Retake the node's screenshot (`Tools/node_shots.py`) and update the input table in `README_ZH.md` (the
   source text), then the same rows in `README.md` and `README_JA.md`.

**Rename or remove an input**: to the upgrade code a renamed input is a removed input plus a new one. In a
file saved earlier the new input gets its default value, the value typed into the old one is dropped, and so
is a wire into it. An object that is baked keeps showing its bake until the user frees it or bakes again.
There is no table of old and new names; if you need one, it belongs in `nodekit._restore_nodes`, with a
case in the `upgrade` test that starts from the old interface. Then search the whole repository for the
old name: the tests, `Examples/make_examples.py` (regenerate the examples), the screenshot tools in
`Tools/`, `translations.ZH`, the three READMEs and their screenshots.

**Add a node**: write `build_<name>()` with `Builder(NAME, KIND, 1, modifier=False)`, an `ensure` function,
an entry in `NODES` (this puts it in the Add menu and the panels), an entry in `SHOTS` in
`Tools/node_shots.py`, tests, translations, a README section. Take the three streams with `_streams(b)` and
pass on the ones you do not change with `_streams_out`.

**Make the solver read a new per-piece attribute**: write it in `build_configure` with `assign(...)` (it keeps
the values of pieces that are not selected), add the name to `core.PIECE_ATTRIBUTES`, read it in
`bake_many` with `em.per_piece(name)` next to the others, and apply it where the bodies are made.

**Change what collides**: bodies are made in `bake_many` from `job.shapes` (the proxy stream) or, without a
proxy, from `rbd_rest`. Shapes are convex hulls, and the code is built around that: `graph.proxy` returns
only the **points** of each piece, and the temporary mesh of a body has vertices and no faces. Setting
`collision_shape = "MESH"` there is not enough. A mesh or compound shape needs the faces carried through:
return topology from `graph.proxy`, build the temporary meshes with faces, and then choose the shape.

**Add an export option**: operator property in `ui.py`, argument in `export.py`, a read-back check in
`Tests/test_export.py`. FBX and VAT export the raw bake; Alembic exports what the viewport shows.

**Change the VAT layout**: everything below reads the same layout and has to change together.
- `export.export_vat` writes the two textures, the mesh with the lookup UV as its second UV set
  (`_lookup_as_second_uv`), and the `.json` (the metadata dictionary is built inside `export_vat`).
  `Merged` changes how many texture columns there are.
- `HStyleRbdVAT.hlsl` decodes the textures; `HStyleRbdVAT_URP.shader` calls it from three passes
  (forward, shadow caster, depth only).
- `HStyleRbdVatSetup.cs` and `HStyleRbdVatPlayer.cs` each have **their own** `Meta` class holding only the
  `.json` fields that file needs. A new field has to be added to the class that uses it. The player reads the
  event times, positions and sizes; `event_speeds` is exported for users and is not read by the player.
- Bump `export.VAT_SCHEMA` and the schema string checked in both `.cs` files, update the layout description
  in the README and in the header of the `.hlsl`, and rerun the Unity check.

**Release a version**
1. Set `version` in `Extension/blender_manifest.toml`.
2. `bash Tests/run_all.sh --installed`.
3. `bash Tools/make_release.sh`, then commit `Repository/`. It holds the zip **without** the version in its
   name, so the link in the READMEs does not change from release to release, and the `index.json` that
   Blender reads (it carries the version, the size and the hash of the zip).
4. Attach `Dist/h_style_rbd_nodes-<version>.zip` (the same bytes) to the release page.

How the drag-and-drop link works: it is the address of the zip followed by
`?repository=.%2Findex.json&blender_version_min=5.2.0`. Dropped on Blender, `./index.json` is resolved next to
the zip, Blender offers to add that address as a repository, and installs the entry of the index whose
`archive_url` is the dropped address. So the zip and `index.json` must be served as plain files from the
same folder, at exactly the address written in the three READMEs. A fork has to put its own address there
and in `website` in the manifest. If `blender_version_min` changes in the manifest, change it in the link.

## 12. Conventions

- Comments say why, in plain words, and mention what was measured. Keep that style.
- Node group names and input names are English and are the user-facing API; do not translate or rename them
  casually (section 5).
- Documentation in every language shows screenshots of the English interface and writes node and input
  names in English, exactly as they appear on the node. A translation of a name goes into the description
  column of the table, never into the name column.
- Positions typed into nodes are in the object's space; only the ground height is in world space.
- One Blender unit is one metre; the scene's unit scale is ignored.
- After any change to `Extension/`: run `Tests/run_all.sh --installed`. After any change to interface text:
  run `Tools/ui_strings.py`.
- Licence: the extension is GPL-3.0-or-later (required for Blender add-ons). The four Unity files in
  `Extension/` are CC0-1.0 so they can be copied into any project; keep their SPDX headers.

## 14. Known limits worth knowing before promising a feature

- Collision shapes are convex hulls; concave pieces are filled in.
- Each piece is a Blender object during the bake: 500 pieces is comfortable, 2000 and more is slow.
- Glue is a set of independent breakable constraints; there is no propagation of stress through the network.
- Crack events are a geometric estimate made after the bake, not a record from Bullet.
- Only the Wind and Force field types were measured; the others go through the same path untested.
- Unity was checked on one version and one render pipeline (URP); Unreal was not checked.
- No fracturing during the simulation, no chipping.
- When an update of the add-on rebuilds a node group, the nodes that use it keep their values and wires but
  lose keyframes and drivers on their inputs (section 7).
